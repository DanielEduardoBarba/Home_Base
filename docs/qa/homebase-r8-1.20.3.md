## New bugs

### Observations (not filed)

- On an IPv4-only listen (`HOMEBASE_HOST=0.0.0.0`), `::1` does not connect. Seat recovery over IPv6 loopback needs a dual-stack / `::` bind.
- `POST /api/login` to `http://[::ffff:127.0.0.1]:port` with an `Origin` header can be `403` `csrf_origin` even though the peer is eligible; the same request with no `Origin` succeeds. Browsers always send Origin, so a user who opens the mapped-IPv6 URL form may need to use `http://127.0.0.1` instead.
- `unlock --mcp` / `--all` removes `mcp_lockout.json` rather than leaving an empty `sources` object.
- `emailGap` text is sometimes the generic “email alerts not configured or no recipient” even when a To address is set but the provider secret is missing (Settings copy, “Needs destination + provider secrets”, is clearer).
